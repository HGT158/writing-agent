# 后续待办

本文件只记录已经确认但不属于当前完成范围的能力。实施任一事项前，必须重新设计并更新架构单一事实来源；高风险或大范围事项应先为关键路径补测试（可采用 TDD），所有事项完成回归验证。

## 后续功能待办（2026-08-22 用户登记）

- **助手记忆系统完善**：
  - 现状：普通写作任务链路会自动沉淀记忆——`finalize_article` 完成文章时登记 articles 索引，Reflect 质检时自动提取 `new_preferences` 写入本助手 `profile.md`，任务启动时 `recall` 注入上下文；
  - 缺口：项目聊天（`chat_project`）不经过 Agent Loop 的 Reflect，长对话中暴露的偏好/风格反馈不会自动进入画像；
  - 方向：聊天轮次终态的选择性记忆沉淀（控制成本、避免每轮写画像）、`profile.md` 的查看/编辑界面（白盒原则：人可手改）、recall 命中与注入内容的可观测性。
- **模型与提供商切换（TRAE 式选择器）**：
  - Agent 面板输入区新增模型选择按钮：菜单内切换当前模型与提供商，并提供"添加提供商"二级入口（填写 base_url、API Key、可用模型）；
  - 现状：模型与提供商由 `.env` 单一配置（`OPENAI_API_KEY`/`OPENAI_BASE_URL`/`MODEL_NAME`），Runtime 启动时初始化唯一 LLM client，无运行期切换能力；
  - 需要：多提供商配置存储、Runtime 热切换或按请求路由、列表/切换/新增提供商的 API、前端下拉菜单与二级菜单交互；
  - 后续增强（在切换功能完成后实施）："添加提供商"表单提供**可用性测试按钮**——点击后用填写的配置向该提供商真实发送一次"你好"，正常收到回复即视为配置可用；结果在表单内原样展示，失败保留填写内容便于修正；
  - 实施前先更新架构（假设 A2、§5.4、§5.9、§5.10）并升版；前端录入的提供商 API Key 的本地存放方案（密钥仍不得硬编码进代码）属实施前必须确认的产品决策。

## 永久搁置（2026-08-22 复议，不再跟踪）

- 中文标点计入 CJK 估算（phase7 P3-4）：估算本不对齐服务端计费口径，标点差异为噪声级。
- 选区工具栏随编辑器滚动（phase7 P3-5）：重选或 Esc 即恢复的纯观感问题，跟随反而可能抖动。

- 跨项目文档标签回退（phase7 P3-8）：不影响打开与 hunk 定位，仅侧栏一行标签显示措辞。
- 首帧主题闪烁预热（phase7 P3-9 部分）：受 CSP 禁止内联预热脚本约束，解 CSP 成本远大于百毫秒级闪烁收益；除非调整 CSP 策略，否则不再跟踪。
